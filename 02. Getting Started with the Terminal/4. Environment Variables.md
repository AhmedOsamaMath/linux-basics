# Environment Variables in Linux

## 1. Introduction

Environment variables are fundamental to the Linux operating system. They are **key-value pairs** that exist in the shell's environment and can affect the behavior of running processes, including the shell itself, scripts, and other applications.

**Purpose:**

*   **Customizing the User Environment:** Users can tailor their shell experience, such as the command prompt appearance or the default text editor.
*   **Informing Scripts:** Scripts often use environment variables to make decisions or to obtain necessary configuration information without hardcoding values.
*   **Controlling Application Behavior:** Many applications check for specific environment variables to alter their functionality, for example, to specify a configuration file location or to enable debugging output.

Think of them as dynamic settings that programs can read to adapt their behavior.

## 2. Viewing Environment Variables

There are several commands to display environment variables:

*   **`env` command:** This command lists all environment variables currently set in your shell session.
    ```bash
    env
    ```
    The output can be quite long, showing variables like `PATH`, `HOME`, `USER`, etc.

*   **`printenv` command:** Similar to `env`, `printenv` lists all environment variables. It can also be used to display the value of a specific variable.
    ```bash
    printenv
    printenv HOME  # Displays the value of the HOME variable
    ```

*   **`echo $VARNAME`:** This is the most common way to display the value of a specific variable. The `$` character before the variable name tells the shell to substitute the variable's name with its value.
    ```bash
    echo $HOME
    echo $USER
    echo $PATH
    ```
    If you try to echo a variable that hasn't been set, it will typically output an empty line.

## 3. Setting Environment Variables

You can set environment variables for a single session or make them persistent across sessions.

### Session-specific Variables

These variables are set for the current shell session only. They will be lost once the terminal or shell is closed.

*   **`VARNAME=value`:** This command creates or modifies a variable within the current shell.
    ```bash
    MY_VARIABLE="Hello World"
    echo $MY_VARIABLE # Output: Hello World
    ```
    **Scope:** Such variables are only available to the current shell instance. They are not passed on to any child processes started from that shell.

*   **`export VARNAME=value`:** This command creates or modifies a variable and then "exports" it, making it available to the current shell and any child processes it starts. This is the more common way to set variables you intend for other programs to see.
    ```bash
    export APP_MODE="development"
    # Now, if you run a script or application from this shell,
    # it can access APP_MODE
    ```

    **Example:**
    ```bash
    # In your terminal
    GREETING="Hello from the parent shell"
    export EXPORTED_GREETING="Hi from the exported parent"

    # Start a new bash sub-shell (child process)
    bash

    # In the new sub-shell
    echo $GREETING           # Output: (empty line, not inherited)
    echo $EXPORTED_GREETING # Output: Hi from the exported parent
    exit # Exit the sub-shell

    # Back in the parent shell
    echo $EXPORTED_GREETING # Output: Hi from the exported parent
    ```

### Persistent (User-specific) Variables

To make environment variables available every time you start a new shell session, you need to add them to specific shell configuration files. These files are read when a new shell starts.

*   Common files include:
    *   **`~/.bashrc`:** This is the most common file for `bash` users (the default shell on many Linux distributions). It's executed for interactive non-login shells.
    *   **`~/.profile`:** This file is read for login shells. It's a good place for variables that should be set once at login and inherited by all subsequent processes. Often, `~/.bashrc` is sourced from `~/.profile` or `~/.bash_profile`.
    *   **`~/.zshenv` or `~/.zshrc`:** If you use `zsh` as your shell, these are the equivalent files (`~/.zshenv` for all zsh invocations, `~/.zshrc` for interactive shells).

*   **Applying Changes:** After adding a variable to one of these files, the changes won't take effect immediately in your current shell. You need to either:
    1.  **Source the file:**
        ```bash
        source ~/.bashrc  # For bash
        # or
        . ~/.bashrc     # POSIX compliant way
        ```
    2.  **Start a new shell session:** Close your current terminal and open a new one.

*   **Example (adding to `~/.bashrc`):**
    Open `~/.bashrc` with a text editor (like `nano`, `vim`, or `gedit`):
    ```bash
    nano ~/.bashrc
    ```
    Add the following line at the end of the file:
    ```bash
    export CUSTOM_DIR="/opt/my_custom_scripts"
    ```
    Save the file and exit the editor. Then, source it or open a new terminal. You can then verify with `echo $CUSTOM_DIR`.

### Persistent (System-wide) Variables

These variables affect all users on the system. Modifying them typically requires administrator (root) privileges.

*   **`/etc/environment`:** This file is a simple way to set system-wide environment variables. It's not a script, so it only accepts `VARNAME="value"` assignments (no `export` keyword, no variable expansion like `$HOME`).
*   **Files in `/etc/profile.d/`:** You can place shell scripts (e.g., `my_vars.sh`) in this directory. These scripts are executed when a login shell is started. This is a more flexible way to set system-wide variables as you can use script logic.

**Caution:** Modifying system-wide files should be done with care, as incorrect changes can affect the entire system. This is usually the domain of system administrators.

## 4. Common and Important Environment Variables

Linux systems come with many predefined environment variables. Here are some of the most important ones:

*   **`PATH`**:
    *   **Role:** This is one of the most crucial variables. It tells the shell which directories to search for executable programs when you type a command. It's a colon-separated list of directory paths.
    *   **Example:** `echo $PATH` might show something like `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`.
    *   **Adding to `PATH`:** To add a directory (e.g., `~/my_scripts`) to your `PATH` for the current session:
        ```bash
        export PATH="$HOME/my_scripts:$PATH"
        ```
        To make this permanent, add the line above to your `~/.bashrc` or `~/.profile`. The `$PATH` at the end ensures you're appending the new directory and not overwriting existing ones.

*   **`HOME`**:
    *   **Role:** Specifies the path to the current user's home directory (e.g., `/home/username`).
    *   **Example:** `cd $HOME` or simply `cd` will take you to your home directory.

*   **`USER`** or **`LOGNAME`**:
    *   **Role:** Contains the username of the currently logged-in user.
    *   **Example:** `echo $USER`

*   **`SHELL`**:
    *   **Role:** Specifies the path to the user's default shell program (e.g., `/bin/bash`, `/bin/zsh`).
    *   **Example:** `echo $SHELL`

*   **`TERM`**:
    *   **Role:** Defines the type of terminal emulator being used (e.g., `xterm-256color`, `linux`). This helps applications format their output correctly for your terminal.
    *   **Example:** `echo $TERM`

*   **`PS1`** (Prompt String 1):
    *   **Role:** This special variable controls the appearance of your primary command prompt. It can include special sequences to display things like the username, hostname, current directory, etc.
    *   **Example:** A simple `PS1` might be `PS1="\u@\h:\w\$ "`, which displays `username@hostname:current_directory$ `. Modifying this in your `~/.bashrc` can customize your prompt.
        ```bash
        # For the current session (try it out!)
        export PS1="MyPrompt> "
        ```

*   **`LANG`** or **`LC_ALL`**:
    *   **Role:** Define locale settings, such as language, character encoding, and date/time formatting. `LC_ALL` overrides all other `LC_*` locale variables if set.
    *   **Example:** `LANG="en_US.UTF-8"`

*   **`EDITOR`** / **`VISUAL`**:
    *   **Role:** Specify the default text editor to be used by other programs (e.g., `git` for commit messages, `crontab -e`). `VISUAL` is typically for full-screen editors like `vim` or `nano`, while `EDITOR` might be for line editors like `ed`. If `VISUAL` is set, it usually takes precedence.
    *   **Example:**
        ```bash
        export EDITOR="nano"
        export VISUAL="vim"
        ```
        (Add to `~/.bashrc` for persistence).

## 5. Unsetting Environment Variables

To remove an environment variable from the current shell environment, use the `unset` command.

*   **`unset VARNAME`**:
    ```bash
    MY_TEMP_VAR="some value"
    echo $MY_TEMP_VAR  # Output: some value
    unset MY_TEMP_VAR
    echo $MY_TEMP_VAR  # Output: (empty line)
    ```
    If the variable was exported, `unset` will remove it from the environment of the current shell and it won't be inherited by new child processes. However, it does not affect already running child processes that inherited the variable.

## 6. Best Practices/Tips

*   **Naming Convention:** By convention, environment variable names are written in **UPPERCASE**. This helps distinguish them from regular shell variables.
*   **System-wide Caution:** Be very careful when modifying system-wide configuration files like `/etc/environment` or files in `/etc/profile.d/`. Incorrect changes can negatively impact all users or even system stability.
*   **Test Changes:** When modifying shell configuration files (`~/.bashrc`, `~/.profile`), test the changes in a new terminal window or by sourcing the file in a non-critical shell first. This way, if you make a mistake that breaks your shell, you can easily fix it without being locked out.
*   **Specificity:** Set variables at the most specific scope necessary. If a variable is only needed for one script, consider setting it within the script or just before running it, rather than globally.
*   **Security:** Avoid storing sensitive information like passwords or API keys directly in environment variables that might be logged or easily inspected. Use more secure methods for handling such data when possible (e.g., dedicated secrets management tools).
*   **`export` Wisely:** Only `export` variables that need to be accessed by child processes. Variables internal to a shell script or the current shell session usually don't need to be exported.

Understanding and using environment variables effectively is a key skill for working proficiently on the Linux command line. They provide a powerful mechanism for configuring your system and controlling program behavior.
